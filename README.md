Research release for static allocation of finite planned bulb-flat stock, controlled remnants, and new purchases, with block isolation and directional material compatibility.

## What is included

- Eight byte-identical frozen computational modules for the formal method, standard-method comparison, and small-case exact/search comparison.
- De-identified input records: 4,555 main-instance parts across 50 blocks, 2,868 finite planned-stock entities, three controlled remnant pools, and directional grade rules.
- Input sets and archived metrics for 27 standard-comparison cases and 15 controlled small cases.
- All 100 formal S0–S4 results, including per-bar and per-part assignments: 20 seeds per scenario.
- Source CSVs for four quantitative manuscript figures, representative entity/part crosswalks, archived auxiliary configuration/result records, and available historical computational snapshots.
- Independent plan validation, integrity manifests, data-field inventory, figure-regeneration code, and opt-in CSV-based solver entry points.

This release documents **finite-resource joint decisions and the resulting procurement/resource trade-offs**. The representative 2.500 m reduction is a traceable example, not the full main-instance claim.

## Quick verification without new experiments

Run commands from this repository's root. The plan verifier uses only the Python standard library.

```bash
python scripts/verify_release.py --report outputs/verification.json
```

Expected checks include 100 formal plans, 455,500 part assignments, 194,494 bars, complete unique demand assignment, finite-entity uniqueness, block isolation, grade/section compatibility, length capacities, and stored aggregate metrics. The paired S3–S4 procurement difference has median **0.037400 t**, with **17 lower / 2 tied / 1 higher** for S4. The documented HP 160 × 10 pair uses the same 35 existing entities and 14 purchases per solution, with purchased length **135.500 → 133.000 m**.

## Actual archived formal budgets

| Scenario | Remnants | Directional substitution | Search stages | Iterations per active geometry per stage |
|---|---|---|---|---:|
| S0 | No | No | One | 500 |
| S1 | HIGH pool | No | One | 500 |
| S2 | No | Yes | Fixed mappings | 500 |
| S3 | HIGH pool | Yes | Fixed mappings | **1,000** |
| S4 | HIGH pool | Yes | Fixed mappings, then joint reassignment | **500 each** |

These are the values stored in the original batch configuration and run records. Each stage uses a 90 s geometry search budget, within a shared 600 s search cutoff. Construction and merging can finish after that cutoff; it is not a total wall-clock runtime guarantee. Formal S0–S4 runs disable local MILP. Small-case search experiments enable local MILP under their separate settings.

## Optional new solver runs

New execution is disabled by default. These commands only load and describe inputs:

```bash
python scripts/run_experiment.py --family main --scenario S4 --seed 1
python scripts/run_experiment.py --family standard --case STD001 --algorithm ALNS --seed 1
python scripts/run_experiment.py --family small --case SMALL001 --algorithm EXACT --seed 1
```

Only adding `--execute` starts an optimizer. Results then go to a new `outputs/runs/` subdirectory and never overwrite archived evidence. No such executions were launched while preparing this candidate. The CSV adapter is new release infrastructure; the eight selected computational modules are unchanged. Inputs/configurations and archived output checks are supplied, not a claim of hardware-independent bitwise stochastic reruns. The original database application is not required. Use a source checkout; this is not a standalone wheel distribution.
